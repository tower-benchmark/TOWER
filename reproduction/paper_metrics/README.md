# Paper metric reference

This standard-library Python reference implements the human-label calculations
in the 2026 manuscript, *TOWER: Benchmarking Bimanual Manipulation Across
Simulation and Reality*, Sections 3.3/4.1 and Appendices A, B, G and I. The
manuscript SHA-256 is pinned in `protocol.json`. `manifest.json` pins this
reference's version, implementation, protocol, documentation, and CSV schema.
Python 3.11 is the repository's supported interpreter.

The reference takes final human episode labels, source ratings and artifact
records as inputs. Supply the evaluated cohort and checkpoint identities with
these records to reproduce the reported tables. Both REAL and SIM use human labels.

## Reviewer commands

From the repository root, without Isaac Sim or any third-party dependency:

```bash
python3.11 -m reproduction.paper_metrics verify
python3.11 -m reproduction.paper_metrics template --output episodes-to-annotate.csv
# Populate the template with final human labels and artifact references first.
python3.11 -m reproduction.paper_metrics aggregate \
  --episodes final-episodes.csv --ratings source-ratings.jsonl \
  --output paper-results
```

Omit `--ratings` if source ratings are unavailable; agreement is then explicitly
unavailable. Each output path must be new. For an explicitly incomplete audit,
add `--allow-incomplete`; missing fields remain unavailable, and cross-domain
summaries are not calculated on a smaller set of configurations. The strict
command rejects missing final labels, missing artifact references, unfinished
annotation status, duplicate identities/evidence, and any group that does not
contain exactly ten valid episodes. Artifact references are trimmed; whitespace-only
references count as missing. Invalid episodes may accompany the 960
valid ones and require a reason external to the policy.

Run the reference regression suite using the repository environment:

```bash
uv run --locked --no-sync pytest reproduction/paper_metrics/tests
```

## Task identity and plans

Paper letters are different from historical numerical IDs. The original IDs
are retained for locating repository scenes; they must not be substituted for
paper letters in the episode CSV.

| Paper task | Family | Legacy ID | 2L G/P | 3L G/P |
| --- | --- | --- | --- | --- |
| A | Cross Transfer | task2 | 2/2 | 3/3 |
| B | Two-Block Transfer | task1 | 4/4 | 6/6 |
| C | Extract and Stack | task6 | 1/1 | 2/2 |
| D | Lateral Insertion | task5 | 1/1 | 2/2 |
| E | Layerwise Pushdown | task4 | 3/3 | 6/3 |
| F | Tool-Assisted Extraction | task7 | 5/3 | 10/6 |

The exact ordered plans are generated by `protocol.operation_plan` and exported
as `operation-plans.json`. Approach, lift, transport and retraction are not
additional steps. C's grasp plus extraction is a single G step. E assigns each
push to its prescribed phase. F counts tool grasp, two tool pushes, tool return,
and two grasp/extract-and-place transfers per cycle. Retries never create extra
success credit.

## Input CSV

`episodes.template.csv` contains the exact required header. The `template`
command expands it into 960 rows with identifiers and planned counts, leaving
**validity and all scores blank**. Replace generated episode IDs as needed to
match your archival identities. UTF-8 CSV follows these rules:

| Columns | Meaning |
| --- | --- |
| `policy` | `pi05`, `starvla` (paper StarVLA-α), `fastwam`, `openwam` |
| `task`, `layers`, `domain` | A–F, 2 or 3, REAL or SIM |
| `episode_id` | Nonempty identity, unique within policy/task/layers/domain |
| `valid`, `invalid_reason` | Explicit 1/0; an invalid trial requires a reason |
| `s` | Binary terminal task success, 0 or 1 |
| `g`, `p` | Successful planned G and P operations, nonnegative integers |
| `d` | Disturbed non-target block-occurrences, nonnegative integer; no upper cap |
| `planned_g`, `planned_p` | Exact Table 4 counts above |
| `annotation_status` | `agreed` or `adjudicated` for final human labels |
| `episode_artifact` | Unique video/trajectory/annotation evidence locator per domain |
| `checkpoint_artifact` | Domain-specific checkpoint identity or manifest locator |
| `preprocessing_artifact` | Normalization and model preprocessing manifest locator |
| `run_config_artifact` | Scene, initialization, seed, prompt, timing and runtime manifest locator |

Locators should resolve in the accompanying artifact release and include
content digests there. The reference checks required locators and preserves
them with episode identities in `result-to-artifact.json`. REAL-trained
checkpoints are evaluated in REAL; SIM-trained checkpoints in SIM. Record
inference seeds and selected layout IDs in the run artifacts.

## Human-scoring instructions (Appendices A.4 and B.1)

Load the fixed operation plan before reviewing a trajectory. Mark each planned
operation successful at most once, including successes after an earlier failed
operation. Keep failed, skipped and unstarted operations in planned totals.
For C, a grasp without full extraction is not a successful G operation.
For D, the block must be released into the prescribed slot. For F, score tool
acquisition, pushes, tool return, and block transfers as separate planned units.

A/B/C/F placements must remain stable for 10 seconds after release; D must remain
in its slot for at least 10 seconds. C's restacking height tolerance is ±15 mm.
Orientation, spacing, insertion, protrusion, tool return and E's prescribed
push displacement/end state are judged from video as specified in Table 5.
Apply Table 5's visual criteria where no numerical tolerance is specified.

For each started operation, count each non-target block whose center translation
is **greater than 10 mm** once. Exclude the current operation's prescribed target
set, fixed foundation and tools. A block disturbed in a later operation counts
again. Disturbances during failed operations remain included. Sum these
operation-local counts to obtain `d`; an episode-wide union (DBC) is incorrect.
This is separate from the derived denominator below, which is not an attempt log.

Terminal success additionally requires all prescribed operations and the stable
final task arrangement. Full G/P progress may still have `s=0`. Episodes have a
420-second limit and execute a prefix of 16 model targets per observation.
Timeout, policy-induced safety stop and irrecoverable policy failure are valid
failures. Hardware/communication failures, missing observations, corrupted
records and incorrect initial scenes are invalid; log the reason.

Two humans annotate each episode. Retain agreed fields and have a third reviewer
adjudicate disputed fields against the video. Keep source ratings and adjudication
evidence linked to the episode. Automatic scores cannot fill missing human labels.

## Equations and outputs

For each valid episode, `C = g + p` and `E = C + 1 - s`.
Each configuration sums counts before division:

- TSR = sum(s) / valid episodes.
- GSR = sum(g) / sum(planned_g); PSR = sum(p) / sum(planned_p).
- LHPR = sum(C) / sum(planned_g + planned_p), with no prefix constraint.
- ODR = sum(d) / sum(E), in block-occurrences per counted step, possibly above 1.

A zero denominator or any missing required value yields null/blank, never zero
or complete-case deletion. `summary.json` stores rates as fractions;
`tables-14-17.csv` displays TSR/GSR/PSR/LHPR as percentages and leaves ODR unscaled.
It also includes mean and **sample** SD (n−1 divisor) of s, g, p, C, d.
`table-2-pooled-odr.csv` pools numerators and denominators across twelve
configurations; it does not average task ratios. Lower ODR ranks first; equal
values share a rank, and rankings require all four policy values.

Cross-domain statistics pair 48 policy/configuration means. Pearson and raw MAE
use successful operation counts. Normalized Pearson, percentage-point MAE and
CCC divide each pair by its planned length. CCC uses population moments. MMRV
uses strict directed ordering comparisons within each configuration, the largest
REAL normalized margin per policy, then equal averaging over policies and
configurations (equations 15–16). A SIM tie can disagree in only one direction;
a REAL tie has zero margin. Zero-variance Pearson and zero-denominator CCC are
unavailable.

## Source ratings and Table 7

`source-ratings.jsonl` contains one JSON object per annotator and episode, with
all five identity fields (numeric `layers`), `annotator`, and numeric `s`, `g`,
`p`; optional `d` is retained only as input validation. Do not supply adjudicated
labels as independent source ratings. Duplicate episode/annotator pairs fail.
Select the first two annotators in Unicode name order before inspecting scores.
Agreement is exact equality of s, g, p, and (g+p)/planned length.

The reference first checks all ten eligible Task A episodes per policy/layer/domain
(80 per domain), then samples five per group without replacement with seed 42.
Every group must have two complete selected source ratings per episode before
the shared RNG is used. An incomplete population yields unavailable agreement
with the affected group counts. The reference freezes a sort/RNG traversal in
`metrics.py` and exports selected identities and annotator pairs for comparison
with the archived Table 7 sample.

## Release runner versus paper reference

The Task B simulator entry point and its automatic completed-prefix/DBC
outputs are integration diagnostics. Appendix I distinguishes them from the
paper's human labels and ODR. See [the paper-metrics reference](README.md#human-scoring-instructions-appendices-a4-and-b1)
for the human-labeling and scoring contract. Use final
human labels for the paper's metric tables.

## Workbook comparisons (reference 1.0.3)

The historical XLSX reader and its Chinese column names are implemented in
`tower_eval.scoring._paper_annotations`, so installed wheels need no repository
root; `annotations.py` and `scoring_cli.py` here re-export them.
Workbook scoring, including `--push-columns paper-phase` (the default) and `arm`,
now runs through `python -m reproduction.paper_metrics.scoring_cli`. This optional
command requires `tower-eval` and its recording dependencies; the existing
`verify`, `template`, and `aggregate` commands remain standard-library only.
`python -m tower_eval.scoring.offline` remains a compatibility entry point.
These historical comparisons retain paper-v1 semantics. For benchmark rules and
explicit input-path selection, use `tower score`.

After intentional changes, bump `VERSION` and run
`python scripts/maintainer/repin_paper_metrics.py`, then
`python -m reproduction.paper_metrics verify`. The manifest includes the two
moved workbook modules. Historical benchmark and golden files are outside this
manifest and remain immutable.
